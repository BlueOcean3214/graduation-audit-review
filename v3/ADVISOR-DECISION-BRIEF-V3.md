# 导师决策简报（V3）

> 目的：把“历史证据层能证明什么、不能证明什么”与“未来生产器要怎么改”分开呈现，请导师逐项决定。本文只给技术事实与建议，不代替决定，不构成契约修订批准。

## 0. 一句话结论

165 条历史记录仍然不含 §7.1 的七个字段；V3 能在**不改原始数据**的前提下，为其建立可复核的外置证据层（5 个字段可派生、2 个不可恢复），但外置层不能把原契约 FAIL 改成 PASS，也不能完成 §5.6.6 的运行时对照。未来是否重跑、是否接受外置层、短期字段语义如何定，需要导师决定。

## 2. 逐项事实与选项

### D1 历史外置证据层

**事实**

- 165 条原始记录 0 条含七字段；预检按 `result_schema.py` 判 FAIL 是正确的。
- V3 对每条记录给出逐字段封套：`run_id/base_sha` 不可恢复；`knowledge_result_ids`、`short_term_injected`、`difficult_flag`、`data_kind` 可外部派生；`memory_injected` 为部分派生。
- 证据链：165/165 prompt 哈希与记录一致；155 条有 config→plan→record 哈希链；B0 10 条按四元组映射；170 条记忆逐条映射 Gold；统计从行重算。

**选项**

- A. 接受外置层，并在论文/答辩中明确“这是审计追溯，不是原始记录”。
- B. 不接受，要求原始记录本身合规（等价于重跑或修订契约）。

**建议**：A。理由：不伪造历史、不改变统计、可复核；但必须同时披露原契约 FAIL。

**对统计/论文的影响**：统计公式不变；论文方法节需说明七字段缺口与外置证据边界。

**是否改冻结设计**：否。

### D2/D3 短期字段：三谓词与 Boolean 语义

**事实**

- 三个事实：槽位开启 80、区块存在 80、反馈历史存在 75。
- 差异 5 条全部是 S7-empty 的 D 组：区块存在，但“已读取反馈数”为 0。
- 冻结设计只给了一个 Boolean 示例，未定义“true”指槽位、区块还是非空历史。
- V3 不输出单一 Boolean；`original_boolean_semantics_decision=pending_advisor_confirmation`。

**选项**

- A. 三谓词并列，永不压成单一 Boolean（最保守）。
- B. Boolean = 区块存在（则 S7-empty 5 条为 true）。
- C. Boolean = 反馈历史存在（则 S7-empty 5 条为 false）。
- D. Boolean = 槽位开启（则只要组别开启就 true，信息量最低）。

**建议**：A 作为历史呈现；若必须给单一 Boolean，建议 C，因为“注入了反馈历史”比“渲染了一个空区块”更接近实验操纵意图。无论选哪个，都需在设计中写明并提升语义版本。

**对统计/论文的影响**：只影响短期操纵的描述与敏感性分析，不影响主统计量；5 条差异需在附录列出。

**是否改冻结设计**：是（仅语义澄清，不改分组/样本/统计）。

### D4 memory 运行时 status

**事实**

- 170 条注入条目可按 content 唯一映射 Gold；type/strength 170/170 一致。
- prompt 渲染层剥离了 `status` 和 `memory_id`；检索层写死 `status="active"`。
- 因此运行时 status 只能是 `inferred/active`，`verification=not_verified`；不能排除“代码路径退化但 prompt 仍显示 active”的情况。
- Gold status 是 `gold_reference`，不是运行时观测。

**选项**

- A. 接受 `inferred/unknown`，并在论文中明确“未直接观测”。
- B. 要求运行时 status 必须可观测（需重跑并采集 `injected.json`）。

**建议**：A（历史）；未来生产器必须采集真实 status（见 D8）。

**对统计/论文的影响**：H4 对“注入了什么记忆”的解释需降级为“按检索层语义推定”；不影响生成文本的统计比较。

**是否改冻结设计**：否（历史披露）；未来生产器规范需新增字段。

### D5 §5.6.6 无法完成

**事实**

- §5.6.6 要求每份 run 的 `memory_injected` 与该样本 `injected.json` 完全一致。
- 快照仓与源码仓均无 `injected.json`；历史运行没有保存该工件。
- 因此 V3 标 `section_5_6_6_status=NOT_COMPLETED`，不能声称公平性检查第 6 条已完成。

**选项**

- A. 如实披露“历史部分未完成”，用 Gold 映射作为替代性追溯，但不称等价。
- B. 重跑 155 条并生成 `injected.json`，B0 仍无法补（冻结不重跑）。

**建议**：A；若导师认为该检查是硬门槛，则只能走 B，且需接受 B0 的 10 条仍不完整。

**对统计/论文的影响**：公平性论证强度下降；需在局限中写明。

**是否改冻结设计**：否（披露）；若改门槛则需设计修订。

### D6 `data_kind` 派生

**事实**

- 8 个样本文件均无原生 `data_kind` 字段；但 `simulation.is_simulated=true`、`gold_standard.simulation=true`，`seed_fixture.py` 强制校验。
- V3 由二者派生 `simulated_learner_fixture`，标 `partially_verified`，并记录“样本无原生字段”。

**选项**

- A. 历史接受派生；未来样本创建时写入原生字段。
- B. 历史也要求原生字段（则 165 条全部不满足）。

**建议**：A。历史派生的语义足够强（模拟标记 + 强制校验 + prompt 绑定），但必须在论文中说明不是 §3.4 的原生字段合规。

**对统计/论文的影响**：不影响统计；影响“数据合规”表述。

**是否改冻结设计**：未来样本生成器需改；历史披露即可。

### D7 是否重跑 155 条

**事实**

- 重跑可让 155 条新数据具备七字段（用新生产器），但仍需同样的模型/配置/样本；成本约 166 次请求、364k tokens、约 2 小时机器时间。
- B0 10 条按设计冻结不重跑，故即使重跑，最多 155/165 满足 §7.1。
- 重跑会产生新数据，旧数据仍需保留并说明关系；统计需明确用哪一批。

**选项**

- A. 不重跑，使用外置证据层 + 披露。
- B. 重跑 155 条，B0 单列，论文用新批次。
- C. 重跑并同时保留旧批次做敏感性对照。

**建议**：暂 A；若导师认为 §7.1 是硬门槛，则 B，且必须在新生产器通过复审后执行。C 成本最高，仅在需要证明“新旧一致”时采用。

**对统计/论文的影响**：B/C 会改变样本批次与可复现性叙述；A 保持现状。

**是否改冻结设计**：B/C 不修改设计文本，但会新增批次与版本说明。

### D8 未来生产器规范

**事实**

- 已实现 `run_provenance.py`：Git 采集、run_id、知识 id、记忆原始对象映射、injected.json、短期三事实、data_kind、严格校验、失败拒绝写记录。
- 已通过 25 个模拟输入测试与 205 个既有 runner 回归；未合并、未正式运行。
- 尚未实现“旧 Boolean 的配置接口”；V3 规范明确在导师批准前不派生旧字段。

**选项**

- A. 批准规范，代码走独立 PR 复审后合并；正式运行前再确认短期语义。
- B. 暂不批准，继续只做历史证据层。

**建议**：A。规范本身不改冻结设计；代码合并也不等于正式运行。

**对统计/论文的影响**：只影响未来批次；历史批次不变。

**是否改冻结设计**：否（规范落地）；短期语义若批准需设计修订。

## 3. 建议的决策顺序

1. D5（是否接受 §5.6.6 历史未完成）——决定是否需要重跑。
2. D7（是否重跑）——决定后续工作量与批次叙述。
3. D1（外置层是否可作为追溯材料）——决定论文写法。
4. D2/D3（短期语义）——决定分析呈现。
5. D4（memory status 披露）——决定 H4 解释强度。
6. D6（data_kind 派生）——决定数据合规章节。
7. D8（生产器规范）——决定未来实验是否启用。

## 4. 无论怎么决定都必须保留的边界

- 不把 `audit_locator` 当 `run_id`，不把 `reviewed_source_commit` 当 `base_sha`。
- 不把 Gold status 当运行时 status。
- 不因外置层 PASS 而把原契约 FAIL 改为 PASS。
- 不回填 165 条原始记录。
- 不在未获批准时把三谓词压成单一 Boolean。
- 不声称 §5.6.6 已完成。
