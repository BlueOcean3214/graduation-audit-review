# 毕业设计实验数据审计：导师决策说明

**日期**：2026-11-24  
**对象**：165 条历史实验记录（主实验 140、subject 补充 10、S7-empty 补充 5、B0 legacy 10）  
**依据**：数据快照 `7b99ad9`、复核源码 `df155a5`、第一版审计 `10a5239`  
**结论先行**：现有数据可以支撑“外置证据层 + 契约修订”的讨论，但不能让原始记录变成符合 §7.1；预检仍应 FAIL，是否重跑由导师决定。

## 1. 实验数据目前能支持什么

- 165 条记录均可稳定定位到原始文件与行号，且都能与对应 Prompt、样本、config 绑定。
- 165 条 Prompt 的哈希与记录中的 `prompt_sha256` 全部一致；155 条新数据还能逐条对上 plan 身份与 plan/config 哈希。
- 170 条注入记忆能与 Gold 样本按内容唯一匹配；memory_type、strength 全部一致。
- 短期记忆、困难标记、知识检索状态都有可复核的 Prompt/配置证据。
- 因此，**描述性统计与分组比较仍然可用**；数据不是“不可用”，而是“原始字段不完整”。

## 2. 哪些原始字段无法恢复

| 字段 | 状态 | 原因 |
| --- | --- | --- |
| `run_id` | 不可恢复 | 生成器从未写入；结果行中没有该字段 |
| `base_sha` | 不可恢复 | 运行时未记录 HEAD/工作树；执行报告里的基线只是报告声明，不是证明 |

这两个字段不能用“看起来合理”的值补齐。V2 改用 `audit_locator`（文件+行号）和 `derived_batch_locator`（由 experiment_id 派生）做追溯，并明确它们不是原始 run_id。

## 3. 哪些字段只能外部派生或推定

- **可外置派生**：`knowledge_result_ids`（本批 config 为空且 Prompt 明示无检索结果）、`short_term_injected` 的三个谓词、`difficult_flag`、`data_kind`（由样本 provenance 派生）。
- **部分可派生、部分只能推定**：`memory_injected`。
  - content、memory_type、subject_key、strength 可由 Prompt + Gold 外置派生；
  - Gold 中的 status 只能作为夹具参考值；
  - 历史运行时的 status 只能推定为 active，不能声称是直接读取。
- `data_kind` 还有一个限制：样本文件本身没有 §3.4 要求的 `data_kind` 字段；V2 的值是 provenance 派生，不是原始样本自带。

## 4. 170 条记忆映射能说明什么、不能说明什么

**能说明**：

- Prompt 中确实出现了这 170 条记忆，且内容与 Gold 唯一对应；
- memory_type、strength 与 Gold 一致；
- 170 条都对应 Gold 的 active/injected，未发现 weakened/resolved 被写入 Prompt；
- 其中 10 条 S4 time_pattern 记忆的展示值为“中等”，Gold 的 key 为“medium”，差异已被记录，不隐藏。

**不能说明**：

- 不能证明运行时读到的 status 就是 active；
- 不能证明历史运行使用的源码就是本次复核的 `df155a5`；
- 不能完成 §5.6.6 要求的 `injected.json` 逐项对照（该文件在快照中不存在）。

因此 V2 把运行时 status 标为 `inferred / not_verified`，而不是写成一个没有证据等级的 `status="active"`。

## 5. 短期记忆的三个谓词

原 §7.1 只有一个 Boolean，无法同时表达三件事。V2 拆开统计：

| 谓词 | 含义 | true / false |
| --- | --- | ---: |
| `short_term_slot_enabled` | 实验组设计是否开启短期槽位 | 80 / 85 |
| `short_term_block_present` | Prompt 是否实际出现短期区块 | 80 / 85 |
| `short_term_payload_nonempty` | 区块是否包含非空学习历史 | 75 / 90 |

差异全部来自 S7-empty 的 5 条 D 组记录：槽位开启、区块存在，但 `已读取反馈数=0`，所以没有实际历史。这个拆分没有修改冻结设计；原 Boolean 到底取哪种语义，需要导师确认。

## 6. B0 映射漏洞如何修复，历史数据是否出错

旧工具用 `(experiment_id, repeat_index)` 做键。B0 remainder 中 S5 与 S7 共用 experiment_id，repeat_index 又都是 0–3，导致 10 行映射只剩 6 个唯一键，S7 覆盖 S5；旧代码只判断“有没有命中”，可能把 S5 记录匹配到 S7。

V2 改为 `(sample_id, experiment_id, repeat_index, run_dir)` 四元组，并检查映射行数、唯一键、逐条字段、ordinal、未使用行；任何不一致都直接失败。实测 10 行、10 唯一键、10 条记录全部唯一命中，ordinal 10/10 正确，错误列表为空。

**历史数据结论**：没有发现 B0 ordinal 被写错；问题是旧校验不能证明正确性。V2 没有修改任何历史记录。

## 7. 哪些事项可以由工程手段解决

- 修复 B0 映射校验并加回归测试；
- 建立外置证据层（V2 JSONL）和哈希清单；
- 把 memory 子字段分级、把短期记忆拆成三谓词；
- 为不可恢复字段提供诚实的追溯结构；
- 在下一批实验中让生成器写入 run_id、运行时 base_sha、注入清单与 data_kind。

这些都已经在 V2 审计工具中实现，且可复现。

## 8. 哪些事项涉及冻结设计，需要导师确认

1. 是否接受“原始记录保留 + 外置证据层”的契约修订，而不是要求 165 条回填或重跑。
2. §7.1 的 `short_term_injected` Boolean 应采用哪种语义（槽位开启 / 区块出现 / 内容非空），或接受三谓词并列。
3. memory 的 runtime status 是否接受 `inferred / not_verified`，还是必须补做 `injected.json` 逐项核对。
4. `knowledge_result_ids=[]` 的空配置派生是否可作为本批的合规证据；未来非空检索批次不能复用。
5. `data_kind` 是否接受 provenance 派生，还是要求样本文件原生带 §3.4 字段。
6. 是否要求在论文中把 `run_id`、`base_sha` 的缺失作为限制明确写出。

## 9. 是否有必要重新生成实验数据

**重跑能修复的**：155 条新数据可以在生成时写入完整七字段（B0 10 条按冻结设计不重跑）。  
**重跑不能修复的**：

- 历史 165 条的运行时 `base_sha` 仍然无法恢复；
- 历史 `run_id` 仍然无法恢复；
- B0 10 条仍是 legacy，不会变成符合 §7.1；
- 重跑是新数据，不是“修复旧记录”；如果替换旧数据，必须重新说明样本、成本和可比性。

**代价**：按执行报告，155 条约需 166 次请求、36 万 tokens，设计估计约 2 小时机器时间；还需重新做质量检查、盲评准备和版本说明。  
**局限**：即使重跑，也无法让“历史批次”本身满足 §7.1；只能让“下一批”满足。

## 10. 建议

建议按以下顺序处理：

1. **保留原始 165 条历史记录**，不改 `results.jsonl`，不伪造 `run_id`/`base_sha`。
2. **接受 V2 外置证据层**作为追溯与审计材料；它不替代原始记录，也不改变预检结论。
3. **memory 运行时 status 降级为 inferred/unknown**；如导师要求 §5.6.6，则补 `injected.json` 或明确记录“无法完成”。
4. **短期记忆采用三谓词并列**；原 Boolean 的语义由导师确认后再写入契约。
5. **修复 B0 校验工具**（已完成），历史数据不重写。
6. **是否重跑 155 条、是否接受契约修订，交由导师决定**；在决定前不把 V2 说成“已合规”，也不声称预检 PASS。

一句话：现有数据适合“保留 + 外置证据 + 契约修订”的路线；重跑是可选的前向修复，不是修复历史字段的唯一办法，也不能修复 B0 与历史 base_sha。
